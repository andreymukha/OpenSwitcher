# Восстановление иконки OpenSwitcher после developer-установки

Дата: 2026-07-23

## Проблема и подтверждённая причина

Debian-пакет корректно устанавливает валидную иконку в
`/usr/share/icons/hicolor/512x512/apps/open-switcher.png`, а desktop entry
использует штатное имя `Icon=open-switcher`.

В пользовательском `~/.local/share/icons/hicolor/icon-theme.cache` осталась
запись от удалённой developer-установки. GTK поэтому разрешает имя
`open-switcher` в уже несуществующий файл
`~/.local/share/icons/hicolor/512x512/apps/open-switcher.png` и не доходит до
системной иконки из DEB.

Гипотеза подтверждена на копии пользовательской темы в `/tmp`: после
пересборки cache устаревшая запись `open-switcher` исчезает.

## Решение

Пересобрать только пользовательский cache темы `hicolor` командой
`gtk-update-icon-cache --force --ignore-theme-index
~/.local/share/icons/hicolor`.

Саму тему, системную иконку, desktop entry, DEB и код OpenSwitcher не менять.
Это устраняет локальный след старой developer-установки без обходного
абсолютного пути и без вмешательства в системный icon cache.

## Проверка

До изменения зафиксировано, что GTK возвращает отсутствующий пользовательский
путь. После изменения GTK должен для размеров 16–512 разрешать имя
`open-switcher` в системный файл `/usr/share/icons/hicolor/512x512/apps/open-switcher.png`.

Также проверяются существование и читаемость системной PNG и сохранность всех
существовавших до работы пользовательских изменений в рабочем дереве.

## Ошибки и откат

Если `gtk-update-icon-cache` завершится с ошибкой, дальнейшие действия не
выполняются. Cache является производным файлом и при необходимости может быть
создан повторно из фактического содержимого пользовательской темы; удаление
пользовательских иконок не требуется.
