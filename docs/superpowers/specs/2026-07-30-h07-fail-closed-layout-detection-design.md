# H-07: fail-closed определение раскладок

**Дата:** 2026-07-30

**Статус:** согласовано

**Область:** H-07, определение пары раскладок и доступности коррекции

## Цель

Устранить ситуацию, когда OpenSwitcher не смог определить реальные раскладки,
но подставил US/RU, объявил конфигурацию строгой парой и разрешил удаляющую и
перепечатывающую текст коррекцию.

Для обычной конфигурации `us,ru` в поддерживаемых окружениях поведение должно
остаться прежним: автоматическая коррекция, F12, исправление Caps Lock и двух
заглавных букв продолжают работать. Ошибка одного внешнего запроса при запуске
не должна отключать эти функции до следующего перезапуска.

## Подтверждённая проблема

`LegacyLayoutBackend` сейчас:

1. запускает `setxkbmap -query`;
2. не проверяет успешность exit status;
3. при ошибке запуска, отсутствии строки `layout:`, неполной или другой паре
   вызывает `default_legacy_layout_pair()`;
4. возвращает `LayoutSetup::StrictPair` для выдуманных US/RU;
5. тем самым разрешает layout-dependent коррекцию.

На GNOME Wayland это дополнительно нельзя исправлять простым обязательным
`setxkbmap`: источником истины там уже служат GNOME input sources, а
`setxkbmap` может описывать Xwayland, быть недоступным или не отражать
настройку compositor.

## Поддерживаемая гарантия

Гарантия относится к двум основным пакетным профилям:

- Cinnamon/X11 с ровно одной английской `us` или `gb` и одной `ru`;
- GNOME/Wayland с ровно двумя XKB input sources: `us` или `gb` и `ru`.

Также X11-стратегия может работать в других desktop environment, если XKB
достоверно возвращает ту же строгую пару и текущую группу. Неизвестный Wayland
compositor не получает предполагаемую US/RU без отдельной подтверждённой
стратегии.

Абсолютная гарантия для всех Linux desktop environment, compositor и
нестандартных XKB-вариантов не заявляется. Такие конфигурации должны безопасно
отключать layout-dependent коррекцию, а не имитировать поддержку.

## Инварианты безопасности и совместимости

1. Отсутствие достоверных данных никогда не превращается в
   `LayoutSetup::StrictPair`.
2. Исходный текст не удаляется, если пара или текущая раскладка не
   подтверждены.
3. Успешно подтверждённая строгая `us/ru` или `gb/ru` сохраняет существующие
   автоматическую коррекцию, F12 и case-only исправления.
4. Конфигурация с дополнительной раскладкой не использует `switch_next` для
   разрушительной коррекции, поскольку следующая раскладка может оказаться не
   целевой. Case-only исправления могут работать, только когда текущая группа
   отдельно подтверждена как English или Russian: они не переключают layout.
5. Преобразование выделенного текста остаётся доступным при
   `Unsupported`, поскольку оно не должно полагаться на предполагаемую текущую
   пару.
6. Ни `setxkbmap`, ни `gsettings`, ни X11 round-trip не выполняются на grabbed
   input path.
7. Обычный успешно определённый режим не получает нового постоянного опроса и
   не увеличивает задержку коррекции.
8. Изменение setup/features публикуется целиком и инвалидирует ранее
   разрешённую отложенную коррекцию.

## Архитектура

### Контекст определяется раньше setup

`RuntimeState` сначала получает `SystemContext`, затем выбирает источник
определения setup. Позднее уточнение контекста, например переход от
неопределённого/X11-заглушки к GNOME Wayland, запускает повторное определение
setup вместе с уже существующим runtime redetection.

Выбор источника изолируется за отдельной стратегией определения setup. Код
коррекции получает только `LayoutSetup`, `FeatureAvailability` и подтверждённый
`CurrentLayoutState`; он не содержит ветвлений по Cinnamon, GNOME или будущему
KDE. Новое окружение добавляется новой стратегией/backend, не новым слоем в
обработке каждой клавиши.

### Явный результат определения

Определитель различает три результата:

- `Confirmed(LayoutSetup)` — источник успешно прочитан и конфигурация
  классифицирована;
- `TemporarilyUnavailable(reason)` — окружение ещё не готово, команда или
  schema временно недоступны;
- `Unsupported(reason)` — источник успешно прочитан, но конфигурация не
  поддерживает безопасную EN/RU-коррекцию.

`TemporarilyUnavailable` и `Unsupported` дают fail-closed
`FeatureAvailability`: automatic/manual word correction выключены, selected
text conversion остаётся включённым. Различие нужно для восстановления и
точной диагностики, а не для разрешения коррекции.

### X11

Setup читается через `setxkbmap -query` вне input path:

- проверяются запуск и успешный exit status;
- требуется непустая корректная строка `layout:`;
- строка `variant:` сопоставляется с тем же числом групп; неподдерживаемый
  непустой variant не выдаётся за обычную `us`, `gb` или `ru`;
- сохраняется реальный индекс каждой группы;
- ровно одна `us` или `gb` и ровно одна `ru`, без других групп, дают
  `StrictPair`;
- одна английская, одна русская и дополнительные распознанные группы дают
  `PairPlusOther`;
- отсутствие EN/RU, дубликаты, пустой или malformed вывод дают
  `Unsupported`;
- ошибка запуска или non-zero status дают `TemporarilyUnavailable`.

Текущая группа и фактическое число групп читаются через XKB `GetState` и
`GetControls`, уже используемые в Cinnamon-ветке. Число групп должно
соответствовать подтверждённому setup, а текущий индекс — одной из
распознанных групп. Старый `xset`/Scroll Lock LED не считается достаточным
доказательством текущей раскладки. Несовпадение числа групп или неизвестный
индекс дают `CurrentLayoutState::Unknown`.

Одного сравнения числа групп недостаточно: `us,ru` может быть заменена на
`us,de` без изменения `num_groups`. Поэтому уже существующий X11 watcher
root-window property events также отслеживает `_XKB_RULES_NAMES`.
`PropertyNotify` только атомарно инвалидирует layout epoch и ставит запрос
существующему background coordinator. Фактический `setxkbmap -query`,
классификация и публикация выполняются вне watcher и grabbed input path.
Таким образом одинаковое число групп не сохраняет доверие к старой паре, но
постоянный setup polling, новый поток и внешняя команда на каждое нажатие не
добавляются.

При `PairPlusOther` legacy-механизм умеет только `switch_next`, но не
`switch_to(target)`, поэтому существующая policy отключает automatic/manual
word correction. Это намеренное безопасное поведение.

### GNOME Wayland

Setup определяется из
`org.gnome.desktop.input-sources::sources`, а текущая раскладка отдельно — из
`mru-sources`:

- ровно два XKB source `us|gb` и `ru` дают `StrictPair`;
- дополнительные sources дают `PairPlusOther`;
- IBus, неизвестные варианты, дубликаты или отсутствие EN/RU дают
  `Unsupported`;
- ошибка чтения GSettings/schema даёт `TemporarilyUnavailable`;
- пустой или временно недоступный MRU не отменяет уже подтверждённую пару, но
  текущая раскладка остаётся `Unknown`, поэтому коррекция не выполняется до её
  подтверждения.

Так setup не зависит от `setxkbmap`/Xwayland и не отключается только из-за
временно пустого MRU.

### Восстановление без постоянной нагрузки

Если setup не подтверждён при запуске, background coordinator повторяет
определение с интервалами 1, 2, 5, 10 и затем не чаще одного раза в 30 секунд.
После подтверждения повторы setup прекращаются. Проверка срока выполняется
внутри существующего coordinator и не создаёт новый поток.

Если тот же ранний сбой оставил автоматически определяемую комбинацию
переключения в состоянии `AutoFallback`, первое успешное подтверждение setup
однократно повторяет auto-detection комбинации и атомарно публикует её в
`InputRuntimeSnapshot`. Ручная комбинация не переопределяется. После успеха
эта проверка также прекращается: постоянный polling комбинации не добавляется.

Если ранее подтверждённый источник временно перестал читаться, последняя
известная пара не заменяется выдуманной. При этом существующая freshness-защита
текущей раскладки истекает и layout-dependent действия приостанавливаются.
После восстановления источника они автоматически возобновляются.

Успешное чтение явно изменившейся неподдерживаемой конфигурации публикует
`Unsupported` и немедленно инвалидирует разрешения старого layout generation.

### Публикация состояния

Setup, compatibility, feature availability и layout state обновляются как одна
логическая runtime-транзакция до публикации нового `InputRuntimeSnapshot`.
При изменении setup увеличивается layout generation. Уже подготовленная
коррекция со старой generation отменяется с сохранением физических событий и
исходного текста.

### Зависимости DEB

Основной способ установки — Debian package, поэтому исполняемые runtime
зависимости объявляются явно:

- `x11-xkb-utils` для `/usr/bin/setxkbmap`;
- `libglib2.0-bin` для `/usr/bin/gsettings`;
- `gsettings-desktop-schemas` для GNOME input-source schemas.

Наличие этих пакетов не заменяет runtime-проверку доступности display/session,
но исключает ложный fail-closed из-за неполной установки DEB.

## Диагностика

Переходы setup логируются через существующий bounded debug logger без текста
пользователя. Записываются strategy, результат, причина, compatibility и номер
generation. Повторяющиеся одинаковые ошибки rate-limit/coalesce, чтобы
неподдерживаемая конфигурация не засоряла журнал.

Настоящая причина недоступности должна отличаться от неподдерживаемой
конфигурации. Нельзя сообщать «US/RU подтверждены», если использован fallback.

## Тестирование

Реализация выполняется через TDD и не использует реальные host input devices.

### Unit и fault injection

- `setxkbmap`: missing executable, non-zero status, пустой/malformed вывод,
  отсутствие `layout:`, только EN, только RU, дубликаты, `us,ru`, `gb,ru`,
  обратный порядок, дополнительная раскладка, пустые и неподдерживаемые
  `variant:`;
- GNOME sources: точная пара, пустой MRU при правильной паре, extra source,
  IBus, variant, malformed flat values и ошибка GSettings;
- XKB current group: обе группы строгой пары, индекс вне пары и несовпадение
  фактического числа групп;
- X11 `_XKB_RULES_NAMES` change: отдельный atomic signal, немедленная
  инвалидация старого layout epoch и one-shot setup redetection даже при том
  же числе групп;
- ни один ошибочный случай не создаёт default US/RU;
- `PairPlusOther` не разрешает `switch_next`-коррекцию;
- transient retry соблюдает интервалы, прекращается после успеха и не вызывает
  detector из input handler;
- recovery из `AutoFallback` однократно восстанавливает автоматически
  определённую комбинацию, публикует новый config generation и сохраняет
  ручную комбинацию без изменений;
- late context upgrade повторно выбирает правильную стратегию;
- смена setup инвалидирует pending correction и атомарно публикует features;
- package gate проверяет три явные runtime-зависимости.

### Интеграционная проверка

После focused и полного безопасного test suite собирается точный DEB. В
сохранённых профилях Linux Mint Cinnamon/X11 и Ubuntu GNOME/Wayland после
чистого входа проверяется:

- обычная `us,ru` определяется как `StrictPair`;
- automatic/manual/case-only функции доступны;
- временно недоступный источник сначала блокирует коррекцию, а затем
  восстанавливает её без рестарта daemon;
- extra layout или malformed fake source не допускает удаления исходного
  текста;
- после успешного определения нет нового постоянного setup polling.

Эта проверка является целевой для H-07. Полная объединённая runtime-кампания
всех исправлений аудита остаётся отложенной до завершения остальных
поведенческих изменений.

## Не входит в H-07

- Полная поддержка трёх и более раскладок.
- Поддержка произвольных XKB/IBus-вариантов.
- Новый backend для KDE Plasma или неизвестных Wayland compositor.
- Изменение комбинаций переключения, словарей или алгоритма выбора коррекции.
- Изменение clipboard-транзакции.
- Новый постоянный polling setup в успешно определённом режиме.
- Удаление или перестройка сохранённой VM-лаборатории.

## Критерии приёмки

1. В двух основных VM-профилях точная `us,ru` после чистого входа всегда
   получает `StrictPair` и прежний набор функций.
2. Отсутствие/ошибка/malformed output не создают `StrictPair` и не допускают
   удаляющую текст коррекцию.
3. Ранний старт до готовности graphical session восстанавливает функции после
   появления достоверного источника без рестарта daemon.
4. Extra layout не вызывает переключение «на следующую» с последующей
   перепечаткой текста.
5. Текущая раскладка подтверждается GNOME MRU либо XKB group, а не
   предполагается по default US/RU.
6. После успешной setup detection число дополнительных setup-запросов не
   растёт со временем.
7. Ни один новый внешний вызов или blocking lock не появляется на grabbed
   input path.
8. Время выполнения самой коррекции не увеличивается из-за H-07.
9. DEB явно устанавливает команды и schemas, необходимые поддерживаемым
   стратегиям.
10. Focused, полный безопасный suite и целевые package-first VM-проверки
    проходят; полный общий runtime campaign остаётся отдельным финальным
    этапом аудита.
