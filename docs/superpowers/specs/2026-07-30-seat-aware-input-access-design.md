# Проект seat-aware доступа к устройствам ввода

**Дата:** 2026-07-30

**Статус:** согласованный проект решения для итоговой проверки перед
планированием реализации

**Ветка:** `fix/seat-aware-input-access`

**Базовый коммит:** `65eed1d18de3d81d9f7eef22ea2ccb91112ba84c`

**Закрываемые замечания аудита:** H-08, M-09 и L-02

## Краткий результат

OpenSwitcher должен получать доступ к физическим устройствам ввода и
`/dev/uinput` через стандартный механизм systemd-logind `uaccess`, а не через
ручную раздачу ACL всем активным пользователям.

Одного исправления udev-правила недостаточно: отзыв ACL не закрывает уже
открытый файловый дескриптор и не снимает существующий `EVIOCGRAB`. Поэтому
daemon дополнительно получает обязательный монитор активной локальной
графической сессии. При потере права работать с текущей сессией он:

1. запрещает новые коррекции и synthetic key-down;
2. выполняет только необходимое освобождение уже созданного synthetic debt;
3. отбрасывает неотправленный текст старой сессии;
4. снимает физический grab и закрывает устройства;
5. остаётся запущенным и автоматически восстанавливает input backend после
   возвращения допустимой активной сессии.

Штатный ввод и коррекция не получают D-Bus-вызовов или ожиданий на горячем
пути.

## Подтверждённые причины

### Неверный порядок udev-правила

Пакет сейчас устанавливает `80-openswitcher-input.rules`. Стандартное правило
systemd `73-seat-late.rules` запускает builtin `uaccess` раньше, поэтому
добавленный на шаге `80` тег уже не обрабатывается для текущего события.

Ручной `open-switcher-input-acl-bridge` появился как обход этого порядка.
Bridge вычисляет декартово произведение:

- всех активных локальных графических UID;
- всех подходящих `/dev/input/event*` и узлов `uinput`.

Из-за этого пользователь одного seat может получить доступ к устройствам
другого seat.

### Отзыв ACL не отзывает открытый grab

logind корректирует возможность нового `open(2)`, но уже открытый дескриптор
остаётся действительным. Процесс может продолжить удерживать `EVIOCGRAB` после
переключения активного пользователя. Это требует runtime-проверки сессии
внутри daemon.

### Ошибки пакетного жизненного цикла скрываются

Текущие maintainer scripts подавляют ошибки `udevadm`, ACL bridge и части
`systemctl`-операций через `|| true`. В результате пакет может считаться
успешно настроенным, хотя старый daemon не остановлен или новые права не
применены.

### Два источника udev-правила

Правило одновременно хранится в Debian packaging и в `dist/udev`. Это создаёт
риск расхождения при последующих изменениях.

## Цели

1. Не выдавать доступ к input-устройствам между разными seat и пользователями.
2. Освобождать уже открытые устройства при потере активной сессии.
3. Не переносить ввод и контекст коррекции через границу сессии.
4. Автоматически восстанавливать OpenSwitcher после возврата пользователя.
5. Сохранить обычную блокировку экрана без ненужного отключения программы.
6. Сделать install, upgrade, reinstall, remove и purge наблюдаемыми и
   идемпотентными.
7. Сохранить ACL, которые после удаления OpenSwitcher обслуживает другое
   udev-правило.
8. Удалить дублирующий источник udev-политики.
9. Не добавлять задержку коррекции и обычной обработки клавиатуры.

## Не входит в работу

- отдельный привилегированный input broker;
- полноценная выдача общего `/dev/uinput` нескольким одновременно активным
  seat;
- защита от полной остановки всего процесса без возможности выполнения хотя
  бы одного его потока;
- изменение алгоритмов коррекции, Caps Lock, двойной заглавной буквы,
  clipboard или переключения раскладки;
- изменение подобранных задержек ввода;
- исчерпывающая multi-seat аппаратная лаборатория;
- универсальный framework Debian maintainer scripts для других проектов.

## Выбранная архитектура

```text
udev rule 70 ── TAG+="uaccess" ── systemd 73-seat-late ── seat-aware ACL
                                                     │
logind system D-Bus ── SessionActivityMonitor ── session lease/generation
                                                     │
                                                     ▼
InputBackendLifecycle ── open/verify/EVIOCGRAB ── keyboard pipeline
```

Механизмы дополняют, а не заменяют друг друга:

- `uaccess` ограничивает новое открытие устройства;
- session lease отзывает уже открытый backend;
- существующие input/synthetic ledgers обеспечивают корректное освобождение
  состояния внутри одного разрешённого input epoch.

## Udev и ACL

### Единственное каноническое правило

Debian source `debian/open-switcher.openswitcher-input.udev` остаётся
единственным источником. `dh_installudev` устанавливает его с приоритетом
`70`, то есть до `73-seat-late.rules`.

Для поддерживаемых keyboard/pointer event nodes и `uinput` правило добавляет:

- стандартный `TAG+="uaccess"`;
- собственный диагностический `TAG+="openswitcher-input"`.

Собственный тег не выдаёт права. Он нужен для ограниченного trigger,
проверки postcondition и безопасной пакетной очистки.

`dist/udev/80-openswitcher-input.rules` удаляется. Непакетный developer
bootstrap не должен снова устанавливать отдельную копию правила.

### Семантика seat

Для input-устройства используется `ID_SEAT`; отсутствие свойства означает
`seat0`, как в logind.

`/dev/uinput` является общим управляющим узлом и не даёт безопасной
изоляции нескольких seat. Поэтому текущая версия выдаёт его только активной
сессии `seat0` через стандартную семантику logind. На другом seat backend
остаётся недоступным и не получает расширенный ACL вручную.

Daemon дополнительно проверяет seat каждого физического устройства перед
grab. Случайно или вручную выданный широкий ACL не должен заставить
OpenSwitcher захватывать устройство чужого seat.

### Роль пакета `acl`

Ручной ACL bridge полностью удаляется из штатного пути. Зависимость `acl`
временно сохраняется только для ограниченной миграции и очистки runtime ACL
старых установок. После завершения совместимости с такими версиями её можно
будет удалить отдельным простым изменением.

## SessionActivityMonitor

### Выбор допустимой сессии

Монитор подключается к system D-Bus logind и рассматривает сессии текущего
effective UID. Допустимой является сессия, которая одновременно:

- `Class=user`;
- локальная (`Remote=no`);
- имеет `Type=x11` или `Type=wayland`;
- имеет `Active=yes`;
- однозначно определяет один seat.

Ровно одна такая сессия создаёт состояние `Authorized`. Ноль сессий,
несколько одновременно активных графических сессий того же UID, ошибка
logind или неоднозначные данные создают `Unauthorized`.

Это сознательный fail-closed выбор: один per-user daemon не может безопасно
решить, какой из нескольких одновременно активных seat он обслуживает.

Обычная блокировка экрана не меняет `Active` у графической сессии, поэтому
сама по себе не отключает backend.

Monitor worker и его первоначальный snapshot создаются до первой попытки
открыть input backend и до публикации готового daemon D-Bus API. Недоступный
logind не считается разрешением по умолчанию: daemon остаётся доступен для
диагностики, показывает ожидание допустимой сессии и пытается переподключиться,
но физические устройства не открывает.

### Подписка, snapshot и lease

Монитор сначала подписывается на изменения logind, затем читает
первоначальный snapshot и повторно сверяет накопленные изменения. Так
исключается окно между первым чтением и подпиской.

Состояние публикуется как небольшой локальный snapshot:

- разрешено ли использование input;
- UID, session id и seat допустимой сессии;
- монотонная `generation`;
- время последнего успешного подтверждения logind.

Плановый authoritative refresh выполняется не реже одного раза в секунду.
Lease считается устаревшей после трёх секунд без успешного подтверждения.
Сигнал logind при нормальной работе обрабатывается немедленно; TTL является
резервом на потерянный сигнал или зависшее D-Bus-соединение.

Горячий input path читает только локальный snapshot. D-Bus-вызовов, mutex с
monitor worker и дополнительной задержки на каждую клавишу нет.

### Жизнеспособность monitor

Потеря D-Bus переводит lease в `Unauthorized`, будит input loop и запускает
ограниченный reconnect. Возврат D-Bus и однозначной активной сессии
публикует новую generation и разрешает обычное восстановление backend.

Panic или завершение monitor worker считается отказом обязательного input
worker. Input backend освобождается, daemon завершается с ошибкой, а
`Restart=on-failure` запускает его заново.

## Граница EVIOCGRAB

Input backend получает generation допустимой сессии до открытия устройств.
Для каждого кандидата проверяются тип, major/minor, udev identity и seat.

Непосредственно перед физическим grab состояние должно оставаться
`Authorized`. Сразу после завершения всех grab выполняется повторная
проверка:

- lease ещё свежая;
- session id и seat не изменились;
- generation совпадает с начальной.

Backend становится `Ready` и начинает публиковать события только после этой
проверки. Несовпадение приводит к закрытию всех частично открытых/grabbed
устройств без запуска коррекции.

Внешняя смена сессии не может быть атомарной с ioctl внутри пользовательского
процесса. Двойная проверка вместе с wakeup и generation делает это окно
ограниченным и не позволяет сохранить backend после обнаруженного перехода.

## Переход в Unauthorized

При обнаружении смены активной сессии порядок обязателен:

1. Атомарно закрывается admission gate для новых writer-транзакций,
   synthetic key-down и replay текста.
2. Увеличивается session generation и будится input loop.
3. Текущая транзакция отменяется. Выполняются только key-up,
   synchronize и другие операции, необходимые для погашения уже созданного
   synthetic debt.
4. Неподтверждённые текстовые/физические события старой generation не
   проигрываются в новую сессию.
5. Сбрасываются word buffer, hotkey capture, modifier/caps snapshot и другой
   переходящий input-контекст.
6. Физические handles освобождаются до ожидания завершения monitor или других
   потенциально блокирующих worker.

При штатно планируемом input loop нормальный сигнал должен приводить к
освобождению backend не позднее 200 ms. Lease TTL в три секунды является
только аварийной верхней границей при потере сигналов, а не обычным временем
реакции.

В точный момент переключения сессии часть уже захваченного, но ещё не
подтверждённого ввода старой generation может быть потеряна. Обычно это один
или несколько символов; теоретическая граница задаётся существующей
ограниченной очередью. Потеря безопаснее передачи текста другому
пользователю.

## Автоматическое восстановление

Когда прежний пользователь снова получает единственную активную допустимую
сессию:

1. logind сначала применяет актуальные seat ACL;
2. monitor публикует новую `Authorized` generation и будит lifecycle;
3. backend немедленно пытается открыться;
4. при короткой гонке ACL/устройства используются существующие retry
   интервалы 0,5 s, 1 s, 2 s и затем 3 s;
5. новый backend начинает с пустого текстового контекста и свежего
   физического snapshot.

Перезапуск tray, ручной restart сервиса и повторный вход не требуются.

## Жизненный цикл Debian-пакета

### Install и configure

На работающей системе порядок следующий:

1. установить правило с приоритетом `70`;
2. выполнить `udevadm control --reload-rules`;
3. ограниченно trigger-нуть поддерживаемые input nodes и `uinput`;
4. дождаться `udevadm settle`;
5. проверить теги и актуальный ACL для существующих допустимых устройств;
6. только после этого запускать OpenSwitcher в активных пользовательских
   сессиях.

Неожиданная ошибка reload/trigger/verification на живой системе не
подавляется: configure завершается ошибкой и daemon не запускается с
неизвестными правами.

В chroot, контейнере сборки или офлайн-образе без работающего udev настройка
правила считается отложенной до загрузки. Это отдельный распознанный режим, а
не маскировка ошибки живого udev.

### Upgrade

Сохраняется уже реализованный H-06 порядок: старые daemon, tray и guardian
останавливаются до распаковки нового binary. Операции получают ограниченный
deadline.

Отсутствующая или ещё не загруженная unit является нормой. Если на живом user
manager старый `/usr/bin/open-switcher-daemon` остаётся запущенным после
остановки, upgrade прерывается до замены файлов. Проверка процесса
основывается на UID и canonical `/proc/<pid>/exe`, а не только на имени.

После распаковки новый udev trigger пересчитывает ACL через builtin `uaccess`.
Это одновременно мигрирует ACL, ранее созданные blanket bridge.

### Remove и purge

Очистка выполняется только для настоящих `remove`/`purge`, но не между фазами
обычного upgrade.

Перед удалением правила root helper сохраняет в закрытом файле под `/run`
ограниченный manifest:

- canonical devnode;
- sysfs identity и major/minor;
- package diagnostic tag;
- только те именованные user ACL, которые соответствуют подтверждённому
  logind-владельцу seat и наблюдались после package-managed udev trigger.

После удаления правила udev перечитывается и устройства trigger-ятся заново.
Для каждой записи сначала повторно проверяется identity:

- если другой rule по-прежнему даёт `uaccess`, ACL не удаляется вручную;
- если `uaccess` исчез, удаляются только записанные user entries;
- ACL других UID, group ACL, неизвестные записи и изменившийся device node не
  затрагиваются;
- результат перечитывается и проверяется.

Manifest и helper не принимают пути из окружения или пользовательских
аргументов. Симлинки, не-character-device, несовпадающие major/minor и
неожиданная udev identity отклоняются.

Повторный запуск после прерванной операции безопасен. `/run` и `/dev` являются
runtime state; перезагрузка также устраняет незавершённый transient manifest
и пересоздаёт ACL из оставшихся правил.

### Наблюдаемость ошибок

Maintainer scripts классифицируют результаты:

- `unit not loaded`, отсутствие активной графической сессии и offline udev —
  допустимые состояния;
- невозможность остановить реально работающий старый daemon, ошибка живого
  udev или неверный postcondition — ошибка пакетной операции;
- неоднозначный ACL, который нельзя безопасно изменить, сохраняется с точным
  предупреждением, а не исправляется вслепую.

Логи не содержат нажатий, текста, clipboard или содержимого конфигурации.

## Тестовая стратегия

### Pure и Rust unit tests

Без реального D-Bus и устройств проверяются:

- матрица `Authorized`/`Unauthorized` для local, remote, tty, X11, Wayland,
  нуля, одной и нескольких активных сессий;
- subscribe-before-snapshot и изменение generation;
- истечение lease, disconnect, reconnect и смерть worker;
- допуск до grab и отказ после post-grab generation check;
- деактивация во время частичной инициализации и writer-транзакции;
- запрет replay событий старой generation;
- разрешение только cleanup key-up после закрытия admission gate;
- автоматическое восстановление с чистым контекстом;
- фильтрация устройств по seat.

### Shell/package tests

Все команды подменяются fake-инструментами в временном каталоге. Реальные
`systemctl`, `udevadm`, `setfacl`, `/dev` и user session не изменяются.

Проверяются:

- приоритет правила меньше `73` и отсутствие второго payload;
- отсутствие blanket ACL bridge в штатном configure;
- install, reinstall, upgrade, failed-upgrade, abort, remove и purge;
- offline udev против ошибки работающего udev;
- bounded stop и проверка оставшегося процесса;
- failure injection по одному разу на каждой критической фазе;
- идемпотентный повтор;
- сохранение ACL при альтернативном `uaccess`;
- отказ от изменения подменённого node или несовпавшего major/minor.

Тесты группируются по слоям. Полный suite не запускается после каждого
маленького изменения: используются узкие red/green тесты и один итоговый
полный gate.

### Package-first VM

Используются сохранённые профили:

- Linux Mint / Cinnamon / X11;
- Ubuntu / GNOME / Wayland.

Проверяется именно собранный DEB:

1. upgrade с текущего `0.1.0-3`;
2. reinstall;
3. remove и purge;
4. ACL до и после каждой операции;
5. переключение между двумя гостевыми пользователями;
6. освобождение grab при уходе сессии;
7. отсутствие replay старого текста;
8. автоматическое восстановление после возврата;
9. обычная блокировка/разблокировка без отключения;
10. основные коррекции, Caps Lock и двойная заглавная после восстановления.

В ВМ не пробрасываются физические input-устройства хоста. Настройки сети,
udev, ACL и user session хоста не изменяются.

Настоящий multi-seat hardware test остаётся финальной отдельной кампанией.
Pure seat matrix и защита в daemon обязательны уже в этой работе.

## Критерии приёмки

Работа готова только если одновременно выполнено следующее:

1. Пакет больше не содержит и не запускает blanket ACL bridge.
2. Правило `uaccess` применяется до `73-seat-late`.
3. Неактивный или чужой seat не допускается к физическому grab.
4. Смена активного пользователя освобождает backend и не переносит старый
   текст.
5. Synthetic debt не остаётся нажатым при деактивации.
6. Возврат пользователя автоматически восстанавливает backend.
7. Блокировка экрана не ломает обычную работу.
8. Upgrade не заменяет binary при доказуемо работающем старом daemon.
9. Remove/purge не оставляет ACL OpenSwitcher и не удаляет ACL другого
   `uaccess` provider.
10. Основные функции OpenSwitcher работают как до изменения.
11. На горячем пути нет D-Bus round-trip и измеримого роста времени
    коррекции.
12. Релевантные unit/package tests и package-first VM matrix пройдены.

## Осознанные ограничения

### Полная остановка процесса

Если весь daemon завис так, что ни input loop, ни monitor, ни systemd stop не
получают CPU, внутренний monitor не может закрыть собственные файловые
дескрипторы. Завершение процесса освобождает их силами ядра. Полное устранение
этого остаточного риска потребовало бы внешнего привилегированного watchdog
или input broker и не входит в H-08/M-09/L-02.

### Общий uinput и несколько seat

Без отдельного broker нельзя безопасно выдать общий `/dev/uinput` нескольким
seat. Текущий дизайн предпочитает отказ на non-seat0 расширению границы
доверия.

### Точное переключение сессии

Небольшой объём неподтверждённого ввода старой generation может быть потерян.
Он намеренно не переносится через security boundary.

## Предполагаемые области изменения

- новый ограниченный модуль monitor/session policy в `src/daemon`;
- интеграция generation и admission gate с input backend lifecycle;
- seat-проверка кандидатов evdev;
- `debian/open-switcher.openswitcher-input.udev`;
- Debian maintainer scripts и узкий privileged cleanup helper;
- удаление `debian/scripts/open-switcher-input-acl-bridge`;
- удаление `dist/udev/80-openswitcher-input.rules`;
- package/Rust tests и VM package-first сценарии;
- русская validation-запись после завершения.

Изменение алгоритмов пользовательской коррекции и подобранных задержек в эту
область не входит.
