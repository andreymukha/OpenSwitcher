# Безопасная транзакция clipboard для преобразования выделенного текста

**Дата:** 2026-08-11

**Область:** M-01, M-02 и M-03 из аудита OpenSwitcher

**Статус:** согласованный дизайн перед реализацией

## 1. Контекст

Преобразование уже выделенного текста временно использует обычный clipboard:

1. запоминает прежний текст;
2. записывает служебный sentinel;
3. отправляет `Copy`;
4. ждёт выбранный текст;
5. записывает преобразованный текст;
6. отправляет `Paste`;
7. после существующего окна совместимости 300 мс возвращает прежний текст.

Сейчас ранний выход через `?` после первой записи может оставить sentinel или
преобразованный текст и не попытаться вернуть прежний clipboard. Финальное
восстановление также выполняется вслепую и способно затереть содержимое,
скопированное пользователем во время операции. Если прежнее содержимое нельзя
прочитать как текст, код в конце очищает clipboard.

Эта подсистема не используется обычной коррекцией слова, автопереключением,
исправлением двух заглавных букв или случайного Caps Lock.

## 2. Принятое пользовательское поведение

- Преобразование выделенного текста не блокируется из-за картинки, списка
  файлов или другого нетекстового содержимого в clipboard.
- Если прежний текст можно надёжно получить, OpenSwitcher пытается вернуть его.
- Если прежнее содержимое невосстановимо текущим backend, операция всё равно
  выполняется. После успешной вставки в clipboard остаётся преобразованный
  текст.
- Служебный sentinel не должен оставаться после штатного отказа, если backend
  позволяет подтвердить, что sentinel всё ещё принадлежит операции.
- Новое содержимое, скопированное пользователем или другой программой во время
  операции, имеет приоритет и не должно заменяться прежним clipboard.
- Обычный успешный сценарий с текстовым clipboard внешне остаётся прежним.

Потеря невосстановимого нетекстового содержимого является осознанным
продуктовым решением. OpenSwitcher не будет задерживать или молча отменять
преобразование ради полной архивации произвольных MIME-типов.

## 3. Цели

1. Выполнять best-effort rollback после каждой ошибки, возникшей после начала
   изменения clipboard.
2. Выполнять тот же rollback при Rust panic с unwinding.
3. Не затирать обнаруженное конкурентное изменение clipboard.
4. Никогда не подменять исходную ошибку ошибкой восстановления.
5. Не добавлять работу в основной путь обработки физической клавиатуры.
6. Сохранить текущие интервалы ожидания копирования и 300-мс окно после paste.

## 4. Не-цели

- Полное сохранение произвольного набора MIME-типов, изображений, метаданных и
  clipboard-manager history.
- Собственный X11/Wayland clipboard server.
- Гарантия восстановления после `SIGKILL`, `abort`, падения процесса или
  отключения питания: в этих случаях `Drop` не исполняется.
- Устранение фундаментального микроокна между последней проверкой clipboard и
  последующей записью. Протокол clipboard не предоставляет атомарный CAS.
- Изменение алгоритма преобразования текста, горячих клавиш или задержек
  синтетического ввода.

## 5. Архитектура

### 5.1. Снимок до первой мутации

До записи sentinel создаётся `ClipboardSnapshot`:

- `RestorableText(String)` — прежний текст прочитан;
- `Unrestorable` — текст отсутствует, имеет другой формат либо чтение не удалось
  подтвердить.

`ClipboardOccupied` допускает короткую ограниченную повторную попытку. Явное
`ContentNotAvailable` не запускает длинный опрос: нетекстовый clipboard не
должен добавлять постоянную задержку.

Вместе со снимком backend по возможности сохраняет наблюдаемую идентичность
clipboard. Для текущего Linux backend это X11 selection owner, доступный и в
текущем Wayland-профиле через XWayland. Проверка оформляется отдельной границей,
чтобы будущий native Wayland backend мог предоставить свой токен без изменения
транзакционной логики.

### 5.2. `ClipboardTransaction`

После снимка создаётся объект-транзакция, который единолично ведёт состояние:

- исходный снимок;
- последнюю строку, которую операция намеревалась записать;
- подтверждённую идентичность владельца после записи, если она доступна;
- последний осмысленный текст операции: скопированный либо преобразованный;
- признак явного завершения.

Намерение записать значение фиксируется до вызова внешнего clipboard API.
Поэтому ошибка, возвращённая после частично применённой записи, не оставляет
транзакцию в ложном состоянии «мутации не было».

Транзакция предоставляет операции узкие методы:

- записать и подтвердить sentinel;
- принять наблюдённый скопированный текст;
- записать и подтвердить преобразованный текст;
- завершить штатно после paste;
- завершить `NoSelectedText`;
- выполнить условный rollback.

Прямые вызовы `set_text()` и `clear()` из основного сценария после создания
транзакции не допускаются.

### 5.3. Условное восстановление

Перед восстановлением транзакция повторно наблюдает clipboard. Старый текст
возвращается только когда одновременно выполняются доступные проверки:

1. текущее значение совпадает с последним значением операции;
2. наблюдаемый owner совпадает с owner после записи операции;
3. состояние не менялось во время согласованного чтения owner/value/owner.

Если owner-проверка недоступна или наблюдение неоднозначно, OpenSwitcher не
рискует перезаписывать clipboard и оставляет текущее содержимое. На текущих
поддерживаемых Linux-профилях owner probe должен быть доступен; это проверяется
в VM.

Если обнаружено чужое изменение, rollback считается безопасно пропущенным.
Это не ошибка операции и не повод повторять запись.

### 5.4. Нетекстовый исходный clipboard

Для `Unrestorable` успешная операция заканчивается сохранением преобразованного
текста. Слепой `clipboard.clear()` после успеха удаляется.

При ошибке до получения выделенного текста транзакция очищает только
подтверждённый собственный sentinel. При ошибке после получения выделенного или
преобразованного текста остаётся последний осмысленный текст, если исходный
clipboard восстановить нельзя.

Если clipboard уже сменился извне, ни очистка, ни fallback-запись не
выполняются.

### 5.5. Ошибки и `Drop`

Штатные пути вызывают явный finalizer и получают типизированный результат.
`Drop` является страховкой раннего `?` и panic. Он выполняет тот же ограниченный
best-effort rollback, не паникует и не блокируется бесконечно.

Исходная ошибка `copy`, `paste`, чтения или записи остаётся основной.
Неудача rollback записывается как отдельный безопасный diagnostic без текста
clipboard и не заменяет основную ошибку.

`Drop` защищает только unwind. Runner уже использует `catch_unwind`, поэтому
обычный Rust panic проходит через destructors до обработки panic.

### 5.6. Результат операции

Булевого `clipboard_restored` недостаточно: `false` сейчас смешивает безопасное
сохранение чужих данных, осознанный fallback и реальную ошибку. Результат
получает типизированное состояние:

- `Restored` — прежний текст возвращён;
- `ConvertedTextKept` — исходный clipboard невосстановим, оставлен результат;
- `ExternalChangePreserved` — обнаружено новое чужое содержимое;
- `RestoreFailed` — восстановление было допустимо, но backend вернул ошибку.

Только `RestoreFailed` печатается как предупреждение. Остальные состояния
нормальны и доступны в обезличенном debug-log.

## 6. Поток выполнения

| Точка | Исходный текст доступен | Исходный текст недоступен |
|---|---|---|
| Ошибка записи sentinel | Условный rollback, исходная ошибка сохраняется | Удалить только подтверждённый sentinel |
| Ошибка `copy_selection` | Условный rollback | Удалить подтверждённый sentinel |
| Copy timeout | Условный rollback, `NoSelectedText` | Удалить подтверждённый sentinel, `NoSelectedText` |
| Ошибка записи converted | Условный rollback | Оставить наблюдённый выделенный текст |
| Ошибка `paste_selection` | Условный rollback | Оставить преобразованный текст |
| Успех | Условно вернуть старый текст | Оставить преобразованный текст |
| Чужое изменение на любом этапе | Не писать в clipboard | Не писать в clipboard |

## 7. Конкурентность и ограничения протокола

Selected-text runner уже обеспечивает single-flight внутри OpenSwitcher.
Конкуренция рассматривается с другими приложениями и clipboard manager.

Пара owner + точное значение существенно надёжнее нынешней безусловной записи.
Она обнаруживает реальные смены владельца и содержимого. Абсолютную гарантию
«никогда» дать нельзя: другое приложение теоретически может записать данные
между последней проверкой и `set_text(previous)`. Это короткое TOCTOU-окно
является ограничением X11/Wayland clipboard, а не поводом полностью отказаться
от привычного восстановления текста.

## 8. Производительность и приватность

- Дополнительные проверки выполняются только в selected-text worker.
- Основной путь ввода и захват физической клавиатуры не меняются.
- В нормальном случае добавляется несколько локальных clipboard/X11
  round-trip, но не новые фиксированные паузы.
- Повторные попытки ограничены существующими временными бюджетами.
- В логи не попадает содержимое clipboard или выделенного текста: только тип
  результата, этап, длительность и обезличенная сводка.

## 9. Проверки

### 9.1. Unit tests без реального clipboard

- failure-at-every-step для чтения, sentinel write, copy, converted write,
  paste и restore;
- ошибка после неоднозначно применённой записи;
- panic на copy и paste с выполнением `Drop`;
- новый owner или новое значение перед rollback;
- одинаковое значение от другого owner;
- смена owner во время согласованного observation;
- `Unrestorable` не запрещает преобразование и оставляет converted text;
- sentinel не очищается, если его уже заменило другое приложение;
- rollback failure не маскирует primary error;
- типизированные финальные состояния и сообщения runner.

Тестовый backend не обращается к clipboard, X11 или Wayland хоста.

### 9.2. Общий gate

- `cargo fmt --check`;
- полный `cargo test --locked --all-targets`;
- существующие package shell tests;
- сборка канонического DEB.

### 9.3. Минимальный VM smoke

На установленном exact DEB в Mint/Cinnamon/X11 и Ubuntu/GNOME/Wayland:

- обычное преобразование с восстановлением прежнего текста;
- преобразование после нетекстового clipboard без отказа операции;
- конкурентная запись уникального текста в окно перед restore без затирания;
- отсутствие sentinel после `NoSelectedText` там, где операция подтверждала
  владение;
- базовые функции обычного ввода не регрессировали.

Полная финальная двухпрофильная кампания остаётся общей проверкой после закрытия
всех оставшихся Medium-задач.

## 10. Статус аудита после реализации

- M-01 может быть закрыт после failure/panic matrix и VM smoke.
- M-03 может быть закрыт в практической границе owner/value checks с явно
  документированным протокольным TOCTOU-ограничением.
- M-02 не объявляется технически исправленным. Он получает статус «принятое
  продуктовое поведение»: невосстановимый non-text может быть заменён ради
  гарантированной доступности преобразования.

## 11. Критерии приёмки

1. Ни один проверяемый ранний выход не оставляет собственный sentinel без
   попытки безопасной очистки или rollback.
2. Прежний текст возвращается в обычном успешном сценарии.
3. Нетекстовый clipboard не блокирует преобразование.
4. После успешной операции с невосстановимым clipboard остаётся converted text.
5. Обнаруженное чужое содержимое не перезаписывается.
6. Ошибка rollback не скрывает первичную ошибку.
7. Panic с unwinding запускает rollback guard.
8. Текущие задержки copy/paste не увеличиваются фиксированными ожиданиями.
9. Unit tests не воздействуют на реальный clipboard или пользовательскую
   сессию.
