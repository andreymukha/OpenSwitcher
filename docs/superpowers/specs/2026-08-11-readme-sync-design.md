# Дизайн синхронизации README

**Дата:** 2026-08-11

## Цель

Устранить содержательное расхождение между `README.md` и `README.ru.md` и
убрать общий пример установки, привязанный к устаревшему Debian revision.

## Обнаруженное расхождение

Коммит `02df387` добавил только в английский README обязательные runtime-пакеты
для определения раскладки:

- `x11-xkb-utils` для `setxkbmap`;
- `libglib2.0-bin` для `gsettings` и `gdbus`;
- `gsettings-desktop-schemas` для схем GNOME.

Эти зависимости подтверждены текущим `debian/control`, но соответствующий блок
не был перенесён в `README.ru.md`. Из-за этого русская версия ошибочно описывает
`libglib2.0-bin` только как опциональную build-зависимость.

Обе версии также показывают установку файла
`open-switcher_0.1.0-4_amd64.deb`, хотя текущий Debian revision уже равен
`0.1.0-8`.

## Выбранный подход

Выполнить минимальную смысловую синхронизацию:

1. Добавить в русские runtime requirements тот же перечень layout-зависимостей
   и пояснение об их автоматической установке через поддерживаемый DEB.
2. Удалить в русской секции build dependencies устаревшее представление
   `libglib2.0-bin` как отдельной опциональной зависимости; оставить
   `lintian` как действительно опциональный инструмент.
3. В обеих командах обычной установки заменить конкретный номер пакета на
   `open-switcher_VERSION_amd64.deb` и явно пояснить, что `VERSION` нужно
   заменить версией скачанного файла.
4. Не переписывать остальные эквивалентные разделы и не добавлять специальный
   скрипт синхронизации двух естественных языков.

Токен `VERSION` выбран вместо буквального `<version>`: угловые скобки внутри
копируемой shell-команды интерпретировались бы как перенаправление ввода.

## Рассмотренные альтернативы

- Обновить пример до `0.1.0-8`: проще сейчас, но README снова устареет при
  следующем Debian revision.
- Полностью переписать одну версию по другой: создаёт большой переводческий
  diff и риск новых смысловых расхождений без практической пользы.
- Добавить автоматический parity-тест: он может сравнить структуру и команды,
  но не способен надёжно доказать смысловую эквивалентность переводов; для
  одного пропущенного блока это лишняя поддерживаемая поверхность.

## Проверка результата

- перечень runtime-зависимостей сверяется с `debian/control`;
- в обоих README отсутствует устаревший `open-switcher_0.1.0-4_amd64.deb`;
- структура соответствующих разделов и команды остаются эквивалентными;
- Markdown-ссылки и fenced code blocks остаются корректными;
- `git diff --check` проходит.
