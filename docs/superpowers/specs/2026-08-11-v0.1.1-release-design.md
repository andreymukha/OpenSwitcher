# Дизайн релиза OpenSwitcher v0.1.1

**Дата:** 2026-08-11

**Статус:** согласовано пользователем

**Ветка подготовки:** `release/v0.1.1`

## Контекст

Публичный GitHub Release `v0.1.0` содержит только первоначальный Debian-пакет
`open-switcher_0.1.0-1_amd64.deb`. После него в `master` вошли исправления
аудита вплоть до Debian revision `0.1.0-8`, а точный пакет `0.1.0-8` прошёл
финальную двухпрофильную проверку в Mint/Cinnamon/X11 и
Ubuntu/GNOME/Wayland.

Обе версии README синхронизированы между собой, но в них остались общие
устаревшие сведения: упоминания «первого релиза», неподдерживаемый прямой
запуск из `target/debug`, неполный список systemd units, уже устранённый
`rustfmt drift` и недостаточно точное описание clipboard policy.

Нужен новый публичный релиз, который не переписывает историю `v0.1.0`,
соответствует текущему коду и содержит новый проверенный DEB.

## Цели

1. Выпустить GitHub tag/release `v0.1.1`.
2. Собрать основной Debian-пакет `open-switcher_0.1.1-1_amd64.deb` из точного
   commit нового релиза.
3. Не менять runtime-поведение OpenSwitcher в рамках релизной работы.
4. Исправить подтверждённо устаревшие сведения в `README.md` и
   `README.ru.md`, сохранив их смысловое соответствие.
5. Связать commit, tag, DEB и SHA-256 так, чтобы опубликованный артефакт можно
   было однозначно проверить.
6. Проверить именно новый DEB автоматическими gates и коротким smoke в обеих
   сохранённых VM.

## Вне границ работы

- новые функции и изменения алгоритмов коррекции;
- изменение подобранных задержек, input lifecycle или backend policy;
- повтор всей fault-injection кампании финального аудита;
- замена asset или перенос существующего тега `v0.1.0`;
- удаление либо пересоздание сохранённой VM-лаборатории;
- изменение host udev, ACL, systemd или физического input state в процессе
  автоматической проверки.

Если при сборке или smoke обнаружится дефект поведения, релиз
останавливается. Исправление оформляется отдельно и после него создаётся новый
точный кандидат; дефект не маскируется изменением документации.

## Рассмотренные варианты

### 1. Новый `v0.1.1` и Debian `0.1.1-1` — выбран

Это обычная новая upstream-версия после уже опубликованного `v0.1.0`.
Debian revision снова начинается с `-1`, а GitHub tag не смешивается с
Debian-схемой версий.

### 2. GitHub Release `v0.1.0-8`

Позволяет опубликовать ранее проверенный DEB без пересборки, но суффикс `-8`
имеет разный смысл в SemVer и Debian versioning. Для пользователей и будущей
автоматизации это создаёт ненужную неоднозначность.

### 3. Обновить существующий `v0.1.0`

Отклонено: перенос опубликованного тега или замена asset разрушили бы
воспроизводимость прежнего релиза и доверие к указанной контрольной сумме.

## Версии и changelog

- `Cargo.toml`: `0.1.1`;
- запись корневого пакета в `Cargo.lock`: `0.1.1`;
- верхняя запись `debian/changelog`: `open-switcher (0.1.1-1)`;
- Git tag: аннотированный `v0.1.1` на точном release commit;
- GitHub Release: `OpenSwitcher v0.1.1`.

Новая запись Debian changelog кратко объединяет уже завершённые после
`v0.1.0` исправления надёжности, безопасности, input lifecycle, layout,
clipboard, settings и package lifecycle. Она не должна заявлять поддержку
непроверенных окружений.

## Изменения README

Обе версии документации изменяются одним логическим набором:

1. Формулировки про «первый релиз» заменяются описанием текущего состояния.
2. GNOME Shell extension явно остаётся не входящим в поставку, без привязки к
   номеру первого релиза.
3. Из developer workflow удаляются команды прямого запуска
   `target/debug/open-switcher*`. Поддерживаемая эксплуатация остаётся
   package-first через установленный DEB и systemd user services; сборка из
   исходников не объявляется отдельной production-установкой.
4. В список устанавливаемых units добавляются
   `open-switcher-xtest-guardian.socket` и
   `open-switcher-xtest-guardian.service`.
5. Удаляется утверждение о существующем `rustfmt drift`, поскольку свежий
   `cargo fmt --check` проходит. Реальное ограничение non-hermetic
   shell/platform tests сохраняется отдельно.
6. Clipboard policy описывается точно: текст восстанавливается на безопасных
   ошибочных путях при отсутствии конкурентного изменения; после успешной
   коррекции нетекстовый clipboard может быть заменён преобразованным текстом.
7. Команда установки остаётся version-neutral:
   `sudo apt install ./open-switcher_VERSION_amd64.deb`.

Проверки документации должны подтвердить паритет fenced-команд, локальные
ссылки, зависимости из `debian/control` и отсутствие старых формулировок.

## Сборка и происхождение артефакта

Работа выполняется в изолированном Git worktree. Пользовательские изменения в
основном рабочем каталоге и сохранённая VM-лаборатория не изменяются.

После завершения metadata/docs commit:

1. фиксируется чистый tracked state и полный commit SHA;
2. `./manage.sh package deb` собирает release binaries и DEB;
3. проверяется package metadata, architecture, payload, права файлов,
   maintainer scripts, desktop files и четыре systemd user units;
4. вычисляется SHA-256 точного `open-switcher_0.1.1-1_amd64.deb`;
5. создаётся `SHA256SUMS`, содержащий имя и digest этого exact asset;
6. DEB сравнивается с проверенным `0.1.0-8` по структуре пакета: допустимы
   новая версия, build metadata и пересобранные binaries, но не
   необъяснённое исчезновение файлов, units или maintainer scripts.

Debug-symbol package (`.ddeb`) остаётся локальным вспомогательным артефактом и
не входит в обязательные assets публичного релиза.

## Проверки

### Локальные gates

- `cargo fmt --check`;
- `cargo check --locked --all-targets --features settings-ui`;
- полная последовательная Rust test matrix с `settings-ui`;
- vendored `uinput` tests;
- package/shell tests, запускаемые Debian build;
- `desktop-file-validate`, `git diff --check` и доступный `lintian`;
- проверка версий в Cargo, Cargo.lock, changelog и DEB.

Известные Unix-socket/D-Bus tests, которым restricted syscall sandbox мешает
через `EPERM` или зависание, выполняются в разрешённой среде либо внутри VM.
Их нельзя молча исключить из итогового результата.

### Двухпрофильный package smoke

Один и тот же DEB с одним SHA-256 устанавливается в сохранённые профили:

- Linux Mint / Cinnamon / X11;
- Ubuntu / GNOME / Wayland.

В каждой VM достаточно проверить upgrade/install exact package, корректную
версию `dpkg`, запуск daemon/tray, отсутствие немедленного restart loop и
базовую коррекцию через виртуальный тестовый ввод. Глубокая аварийная матрица
не повторяется, поскольку runtime-код по отношению к уже проверенному
`0.1.0-8` не меняется.

## Публикация

Публикация разрешена только после зелёных gates:

1. release commit интегрируется в `master` и отправляется в `origin`;
2. аннотированный tag `v0.1.1` создаётся на этом exact commit и отправляется в
   GitHub;
3. GitHub Release получает assets:
   - `open-switcher_0.1.1-1_amd64.deb`;
   - `SHA256SUMS`;
4. release notes на русском перечисляют основные изменения, проверенные
   окружения, команду установки и SHA-256;
5. после публикации через GitHub API повторно сверяются tag target, имена,
   размеры и digests assets.

Локальный `gh` сейчас не имеет действительной авторизации. Если она не будет
восстановлена, финальная публикация выполняется пользователем одной заранее
подготовленной командой после того, как commit, tag, пути и SHA будут показаны
для проверки.

## Политика ошибок и последующих исправлений

- До публикации неуспешный кандидат можно исправить и пересобрать; старый
  artifact после этого больше не используется.
- После публикации assets и tag `v0.1.1` не заменяются. Существенный дефект
  требует следующей версии.
- Старый `v0.1.0` остаётся доступным как исторический релиз.
- VM-лаборатория сохраняется; её удаление возможно только по прямой просьбе
  пользователя.

## Критерии готовности

Релиз считается завершённым, когда:

1. runtime source diff относительно текущего `master` пуст;
2. версии согласованы как `0.1.1`, `0.1.1-1` и `v0.1.1`;
3. оба README актуальны и смыслово согласованы;
4. локальные gates и два VM smoke прошли на одном exact DEB;
5. SHA-256 зафиксирован и совпадает локально, в обеих VM и в GitHub asset;
6. tag указывает на проверенный release commit;
7. публичная страница релиза содержит новый DEB, checksum и корректную
   инструкцию установки.
